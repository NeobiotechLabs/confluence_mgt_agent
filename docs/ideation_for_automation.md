# 자동화 루프의 개선하기를 위한 고민

## 문제점

- 현재 방식으로는 정말 지속적으로 운영될 수 있는건지 의문이 듦
- Auto PR을 관리하기 너무 힘들거 같다는 생각이 듭니다.

## 구체적이진 않지만 잡다한 생각들 아래와 같이 해보면 어떨까?

- Auto PR 보다는 그날 그날 의 Automation 실행의 결과를 AA space에 남겨준다.
- 루트 위치에 이관 결과 라는 is-folder 타입의 페이지를 만든다 (예정)
- actions 실행의 결과를 아래와 같은 내용을 포함해서 자동 작성해 준다.
    . 페이지 제목 : auto_report_{YYMMDD}_{HH:MM}
    . 내용
        - 각각 Space 별 신규 생성 페이지 이름과 링크 (이관 후보)
        - 이중 선별되어 이관된 페이지와 탈락된 페이지
            . 이관된건 사유와 이관 위치, 지정한 Label (AA 내 경로, 이 경로 및 를 선택한 이유)
            . 탈락된건 탈락 사유
            . 애매한건 미분류 폴더에 그리고 AI의견 (추가 폴더가 필요한지 등)
        - 자가 정화 내역
            . 이전에 배치된 페이지도 다시 검토해서 정책이 변경되었으면 올바른 위치로 재이동
            . 마찬가지로 재이동 사유.
- 그리고, actions 의 결과로 관리자에게 질문과 권고 사항
    . 이 내용을 기반으로 로컬에서 다시 업데이트 (필요하면 코드 정책 지침 어느것이든)
    . 자동으로 하지 않는다, 어떤 경우엔 여러개 몇일분 모아서 할 수 있다.
- 이런 식으로 당분간 안정화 될때까지 업데이트 하면 어떨지.


## 추가 사항
- 당분간 안착할때까지 메일 confluence에 접속해서 이관 결과 페이지를 확인할거야. 굳이 SLACK 및 EMAIL noti 필요없음
- 현재 audit:aa를 보면 최상위 폴더만 확인하는것 같은데, 폴더 구조 전체를 봐야함. IS-FOLDER 레이블 활용
- 페이지 위치를 룰 혹은 AI 기반으로 넣더라도 위 폴더 구조의 적합한 위치에 넣어야지. 애매하면 미분류 하더라도 (실수는 할 수 있고 업데이트 하겠지만) 막 아무데나 최상위 위치에 넣으면 안됨. 그리고 막 폴더 만들고 그럼 안됨 -> 이건 위 리포트에 넣어줘. 다시 개선 할 수 있도록
- 정말 단순 룰기반으로 장기적인 운영이 가능할까? AI와 잘만들어진 지침 같은걸로 해야 하지 않을까?
- 일단 AI는 CLAUDE 말고, MINIMAX 사용 예정이야, 이걸 고려해주고, 추후 GLM 등 다른 모델을 쓸 수 있으니 그게 고려 되어야 해.
- 자가 정화 기능 꼭 필요해 이전에 잘 못 넣었더라도 계속 개선 될 수 있도록

# 검토 및 보완 (2026-07-29, Claude)

> 아래는 위 아이디어를 현재 코드(`audit_aa_space.js`, `reorganize_aa_space.js`, `engine.js`, `confluence_automation.yml`)에 비춰 검증한 결과.
> 원칙: **좋은 직관은 채택, 성립하지 않는 전제는 교정, 빈 메커니즘은 구체화.**

## 1. 총평

**방향은 정확하다.** 특히 "Auto-PR이 문제"라는 직관은 본인이 생각하는 것보다 더 맞다 — 이건 "관리하기 힘든" 수준이 아니라 **데이터 손실** 구조다 (아래 §3). 리포트를 Confluence에 남기고 사람이 모아서 처리한다는 큰 그림도 운영 현실(관리자는 Confluence에서 산다)에 맞다.

다만 제안을 그대로 만들면 새로 생기는 문제가 3개 있다:
1. **자가정화 폭주** — AI는 비결정적이다. 매일 재분류하면 페이지가 매일 이사한다 (§4.3).
2. **봇의 자기 출력 재귀** — 봇이 만든 리포트 페이지를 봇이 다시 스캔/이동하려 든다 (§4.1).
3. **학습 경로 실종** — PR을 없애면 "사람의 결정이 시스템에 반영되는 길"이 사라진다. 새 경로를 명시적으로 설계해야 한다 (§4.2).

이 세 가지만 막으면 제안은 성립한다.

## 2. 약점 / 리스크 분석 (심각한 순)

### 2.1 [치명] 자가정화의 판정 기준이 정의되지 않음
"정책이 변경되었으면 재이동"이라 했는데, **"정책이 변경되었다"를 누가 어떻게 판정하나?** 그리고 AI 분류는 모델·프롬프트·버전에 따라 결과가 흔들린다(MINIMAX→GLM 교체 시 대량 재분류 확정). 판정 기준 없이 "다시 검토해서 옮긴다"를 구현하면:
- AI가 어제는 A, 오늘은 B라 해서 페이지가 매일 이동 → 사용자가 봇을 불신하게 됨. 오배치보다 해로움.
- **대책**: 이동은 **결정적 층(규칙/사람 정책)만** 실행. AI 의견은 **조언 전용**으로 리포트에만 싣고 절대 자동 이동하지 않음. + 이동 예산(1회 실행 ≤ N건), 재검토 쿨다운(예: 30일), `human-classified` 불가지, 최초 N주 dry-run. (§4.3)

### 2.2 [치명] 봇 출력의 재귀 오염
봇이 AA 스페이스에 리포트 페이지를 쓰는 순간, 그 페이지들은 `listAAPages`가 순회하는 222개에 포함된다. 자가정화가 "정책에 안 맞는 페이지"라며 **리포트 폴더를 미분류로 옮기는** 사고가 실제로 가능하다.
- **대책**: `이관 결과` 폴더에 `is-folder` + 리포트 페이지에 `bot-report` 라벨. audit/reorganize/migrator 전부 `bot-report` 라벨 페이지를 **무조건 스킵**. 자기 출력 배제는 설계의 첫 줄에 명시해야 함.

### 2.3 [중요] "스페이스별 신규 생성 페이지"는 현재 audit/reorganize의 관할이 아님
문서의 리포트 내용은 사실 **서로 다른 두 루프**를 섞고 있다:
- **루프 A (스페이스 간 이관)**: SD/WND/Device/SmileArch → AA. "신규 생성 페이지/이관 후보/탈락" = `migrator.js`의 일.
- **루프 B (AA 내부 정비)**: AA 내 배치·라벨·자가정화 = audit/reorganize의 일.
현재 워크플로가 A·B를 한 줄(audit→reorganize→migrate)로 묶어놔서 구분이 흐려진 상태. 리포트도, 실행 주기도 분리해야 한다: **B는 매일(저렴·저위험), A는 주간(고위험·검토 부하 큼)**.

### 2.4 [중요] 리포트 방식에서도 "결정의 저장" 문제는 남는다
PR을 리포트로 바꾸면 *가시성*은 해결되지만, "사람의 결정을 시스템이 다음부터 따르게 하는" 메커니즘은 별도로 필요하다. 리포트만 쌓이고 반영 통로가 없으면 매일 같은 질문이 올라온다.
- **대책**: 정책의 소스를 Confluence의 **"AA 스페이스 운영 정책 가이드" 페이지**(이미 최상위에 실존)로 삼고, 봇이 실행마다 이 페이지를 읽어 AI 프롬프트에 주입. 관리자는 git을 안 건드리고 UI에서 정책을 고치면 다음 실행에 반영. 코드/구조 변경만 git PR. (§4.2)

### 2.5 [중요] 모델 교체(MINIMAX/GLM)의 실제 리스크는 "프롬프트"가 아니라 "환각"
포트/어댑터 구조(`classifiers/*`)라 모델 추가 자체는 쉽다. 진짜 리스크:
- 모델이 **존재하지 않는 folder ID를 반환**할 수 있음 → 반환값은 반드시 `aaTree` 폴더 ID 집합으로 검증, 실패 시 fallback.
- 비결정성 → §2.1의 폭주와 결합. `temperature=0`으로도 버전 차이는 못 막음.
- 비용/속도: 222페이지 × 매일 AI 호출은 낭비. **(제목+부모경로+정책해시) 기준 캐시**로 미변경 페이지는 재호출 금지.

### 2.6 [경미] 알림 완전 제거는 비추 — "실패 시" 이메일은 남겨야
제안대로면 실행이 크래시했을 때 **리포트 페이지가 안 생기는 것**이 유일한 신호인데, 이건 "오늘 리포트가 없네?"라고 사람이 알아챌 때만 보인다. 자격증명 고장이라 Confluence에 못 쓰는 상황이면 신호 자체가 없다.
- **절충**: 성공 알림·Slack 제거 동의. **실패 전용 이메일(`notify-failure`의 이메일 부분)은 유지** — 리포트 체계의 심박동 보증 장치.

### 2.7 [경미] "당분간 안정화될 때까지"의 졸업 기준이 없음
종료 조건이 없으면 "당분간"은 영원이 되고 관리자의 주의는 먼저 끊긴다. 측정 가능한 기준 필요. (§4.7)

### 2.8 [경미] 리포트 제목/형식
- `auto_report_{YYMMDD}_{HH:MM}`의 콜론은 안전한 문자가 아님 → `auto_report_260730_0900` 권장. 동일 시각 재실행 충돌 방지용 run 구분 포함.
- 리포트는 **실행 가능해야** 함: 항목마다 "관리자 조치 필요 Y/N", 그리고 **지난 실행 대비 diff**(신규 vs 반복 미해결) 섹션. 안 그러면 관리자가 매일 전체를 다시 읽게 됨.

## 3. 핵심 발견 — Auto-PR 제거는 "안전"하다 (제안을 뒷받침하는 코드 근거)

PR이 실어 나르던 `classification_decisions.json` 항목의 실제 가치를 코드에서 확인했다:

- `commitDecision`은 페이지 제목 전체를 `escapeRegex`로 정규식화해 저장 → **동일 제목의 페이지만 매칭**. 학습이라기보다 "제목 핀고정"에 가까워 범용 가치가 거의 없음.
- 사람의 이동은 **PR 없이도 이미 존중**된다: `reorganize_aa_space.js`는 중첩 페이지(폴더 안에 있는 페이지)를 구조적으로 스킵(`if (p.parentId && !isAtTopLevel(...)) continue`). 사람이 폴더로 옮긴 페이지는 봇이 절대 건드리지 않음.
- 결론: **Auto-PR은 거의 무가치한 데이터를 위해 머지 의례만 요구하던 장치.** 제거해도 사람의 의도 존중은 훼손되지 않는다. "관리 부담"이 아니라 "없애도 되는 것"이었다.

※ 전제 조건: 위 3가지는 `human-classified` 라벨 보호, 중첩 스킵이 유지될 때 성립.

## 4. 보완 설계 (목표 아키텍처)

### 4.1 리포트 체계 (제안 채택 + 재귀 방지)
- AA 홈 아래 `이관 결과` 폴더(`is-folder` + `bot-report`), 하위에 일일 리포트 `auto_report_YYMMDD_HHMM`.
- 봇의 모든 루프는 `bot-report` 라벨 페이지를 스킵(자기 출력 배제).
- 리포트 섹션: ① 요약 계수 ② 루프A 이관(후보/이관/탈락+사유) ③ 루프B 내부 정비(이동 내역+이유+AA내 경로) ④ **AI 권고판(실행 안 함**: 오배치 의심, 신규 폴더 제안, 반복 애매 항목) ⑤ 관리자 조치 체크리스트(신규 vs 반복 미해결 diff) ⑥ 사용된 정책 버전(정책 페이지 해시)·모델명·실행 메타.
- 리포트 생성 전 동일 제목 존재 확인(재실행 중복 방지). 보존 정책(월간 롤업)은 나중 과제.

### 4.2 학습 루프: PR 제거 후 정책 반영 경로
- **Auto-PR 단계 제거** (`peter-evans/create-pull-request` 삭제).
- 반영 통로: **리포트(입력) → 관리자 검토 → Claude와 대화로 정책 업데이트 → 봇 다음 실행 반영**. 자동화하지 않고 며칠 치를 모아서 처리(원안 유지).
- 정책 보관 위치 — **(A) git 보관 권장** (2026-07-29 대화에서 교정. 초안은 Confluence 정책 페이지였으나, "업데이트 주체 = UI의 관리자가 아니라 Claude 대화"라는 실제 워크플로에서 전제 변경):
  - **(A) git**: 소프트 지침 `config/aa_policy.md`(자연어, AI 주입 전용·비파싱) + 하드 규칙 `config/categories.yaml`(regex·folder ID, 파싱·사전 검증 대상). Claude가 대화에서 편집 → 커밋/PR/머지 → 다음 cron 반영. 이력·diff·사전 검증 무료. 하드 규칙은 어떤 경우에도 git 유지.
  - (B) Confluence 페이지: 봇이 런타임 fetch. 장점은 비개발자의 UI 즉시 편집뿐 — 현 워크플로에선 이점이 작고 이중 관리 비용이 큼.
  - 되돌릴 수 있는 선택: 나중에 비개발자 UI 편집 필요가 생기면 소프트 지침만 Confluence 페이지로 승격.
- 위치 무관 필수 요건: 봇은 정책을 **실행마다 런타임에 읽음**(git이면 main checkout) + 리포트에 **정책 버전(해시) 기록**(자가정화 "정책 변경 시 재검토"의 기준점) + 리포트 끝에 **구조화된 제안 섹션**(규칙 승격 후보·신규 폴더 제안·조치 필요 항목 — 이 섹션이 있어야 대화가 생산적).
- 명시적 핀 = Confluence 라벨(`human-classified`)이 이미 권위 저장소.
- `classification_decisions.json`: 즉시 폐기 대신 **점진 축소**(기존 엔트리는 유지, 신규 `commitDecision`은 중단 → 리포트의 "규칙 승격" 후보다루기).
- **규칙 승격 루프**: 리포트가 "AI가 이번 주 30건을 폴더 X로 분류"처럼 반복 패턴을 제시 → 관리자가 주 1회 `categories.yaml`에 규칙 한 줄 추가(git PR) → 그 패턴은 이후 AI 비용 0. 이게 "단순 룰 vs AI" 질문의 답: **규칙=확정 뼈대, AI=롱테일, 사람=오버라이드**, 그리고 AI 결정을 규칙으로 승격시키는 피드백.

### 4.3 자가 정화 (요구사항 채택 + 폭주 방지 장치)
- **이동 권한은 결정적 층(규칙/사람 정책)만** 가진다. AI는 기배치 페이지에 대해 이동 불가, 리포트 권고만.
- 발동 조건: 배치 시점 정책해시 ≠ 현재 정책해시(정책이 실제로 바뀐 페이지만 재검토) + 정기 샘플링.
- 가드: `human-classified` 불가침, 재검토 쿨다운(30일), 실행당 이동 예산(≤10건, 초과분은 리포트 이월), 첫 N주 dry-run, 모든 이동 전/후·사유 리포트 기록.

### 4.4 두 루프 분리
- 워크플로 job 구성: `aa-hygiene`(매일: audit+자가정화+리포트) / `cross-space-migration`(주간: 후보→이관, 같은 리포트의 별도 섹션 또는 별도 리포트). 실패 알림은 둘 다 이메일 전용.

### 4.5 AI 모델 추상화 (MINIMAX → GLM)
- `AI_PROVIDER=minimax|glm|claude` 환경변수 + 공용 프롬프트/JSON 스키마/검증/캐시를 가진 단일 AI 어댑터(프로바이더 클라이언트만 교체). 기존 `classifiers/claude.js`는 옵션으로 존치.
- **검증**: 반환 folderId ∈ `aaTree` 폴더 집합, 아니면 fallback. **캐시**: (제목+부모경로+정책해시+모델) 키. `temperature=0`.

### 4.6 알림 정책
- Slack 제거, 성공 알림 없음(리포트가 그 역할). **실패 전용 이메일 유지** — 자격증명/러너 사망 시 유일하게 살아남는 채널.

### 4.7 안정화 졸업 기준 (측정 가능하게)
아래가 **2주 연속** 충족되면 일일 검토 → 주간 스팟체크로 전환:
- (a) 미분류 순증 0, (b) 사람 수동 정정 0, (c) 실행당 AI 권고 < N건, (d) 실패 0.

## 5. 기존 코드에서 즉시 고칠 버그 (리뷰 중 발견 — 개선 선행 조건)

1. **`last-parent-*` 라벨 누적 (감시 오염)**: `stampLastParent`가 새 라벨만 추가하고 옛 라벨을 제거 안 함. 페이지에 라벨이 여러 개 쌓이면 `detectMove`의 `find()`가 **오래된 라벨을 첫 매칭**으로 잡아 허위 이동을 감지 → 허위 학습. 자가정화를 얹기 전에 반드시 수정(스탬프 시 기존 `last-parent-*` 제거).
2. **dry-run 카운터 버그**: `reorganize` dry-run이 `[DRY]` 줄을 출력해도 `moved++`가 EXEC 분기에만 있어 "would move: 0"으로 표시. 경미하나 리포트 신뢰성 차원에서 수정.
