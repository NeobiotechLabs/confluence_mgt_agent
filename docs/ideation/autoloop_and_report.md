# LLM 기반의 분류와 분류 결과 리포팅

정제되진 않았지만, 전반적인 내생각

## 대략의 워크플로우

1. github action으로 자동 trigger 된다.
2. 우선 SD/WND/Device 등 연관 된 Space를 탐색한다.
3. 신규 등록되거나 업데이트 된 페이지를 찾는다. 기간은 정해야 함 (1주일? 아님 그날꺼만?)
4. 3번에서 찾아진 페이지는 이관 후보 페이지가 된다.
5. 우선 이미 이관 되었거나, 이전에 이관에서 탈락한 후보는 제외한다. 
    단, 이미 이관된 경우에도 변경이 있으면 업데이트 필요함
6. LLM 과 지침 그리고 현재 폴더 구조 를 활용해서 페이지별로 이관될 위치를 선정한다.
7. 6번 중 업무적인게 아니라 너무 의미없는 페이지는 걸러낸다. (탈락 후보)
8. 6번 중 이관 후보라 할지라도 적당한 위치가 없다고 판단되면 미분류 폴더로 보낸다.
9. 외부 이관이 끝나면 내부 페이지들을 살펴 보고 잘못된 위치에 가있는 페이지를 선별한다. (자가 정화)
   단, 아직 이동을 하지 말고 자동화 리포트에 반영한다.
10. 마지막으로 자동화에 대한 리포트를 남긴다.
   - 페이지 제목 형태: 자동화_리포트_{YYMMDD}_{HH:MM}
   - 1 요약 : 현재와 같음 AA 총페이지, 최상위 고아 페이지, 미분류 페이지, 자동이동 (루프B), 실행경고, 관리자 조치 필요
   - 2번 에 표로 
     . 전체 3번에서 찾은 이관 후보 페이지를 나열하고, 이관 여부 위치, 해당 위치 이동 근거
     . 그 다음에 미분류 폴더 이동한 페이지들 리스트, 미분류 근거, 권장 조치 사항
     . 이관 탈락 페이지 리스트, 탈락 사유
   - AI의 권고 및 질문 사항
     . LLM 지침을 업데이트 하라던가, 폴더 구조를 바꿔보라던가 혹은 추가해보라든가 등등
     . 아니면 이런경우는 앞으로 어떻게 할지? 같은 사용자에게 질문?
11. 관리자는 자동화 리포트의 내용을 확인하고, 지금처럼 AI 통해 LLM 지침이나 룰을 개선한다. 정착될때까지
12. 이러한 것들은 로컬에서 테스트 해볼 수 있어야 됨.
